# Design — 002 Keep tasks in Postgres, answer 503 and report not ready while the database is down

## Decisions

- **Postgres through psycopg 3, our own small pool, client-side deadlines, in-service migrations.** Rationale and
  trade-offs in [ADR-001](../../adr/001-postgres-access-psycopg-in-service-migrations.md). In short: `psycopg_pool`'s
  background reconnect backoff cannot guarantee that the *next* request after an outage succeeds (AC-002.10,
  AC-002.11), and a server-side `statement_timeout` does not fire when the server does not run at all (AC-002.6),
  so the pool opens connections on demand in the request's worker and every operation has a client-side deadline.
- **The HTTP layer is unchanged** (AC-002.3): same routes, same `TaskCreate` / `Task` models, same FastAPI 422
  body. `TaskCreate` is validated by FastAPI before the handler runs and before any database dependency is used,
  so invalid bodies answer `422` while the database is down (AC-002.4). The store dependency never touches the
  database when it is built; only `TaskStore.add` / `TaskStore.list` do.
- **`TaskStore` keeps its name and interface** (`add`, `list`) and becomes Postgres-backed; the in-memory
  implementation is removed. Its dependency `get_task_store` now depends on `get_database`.
- **One global order:** `GET /tasks` orders by `seq bigserial` (AC-002.1, AC-002.2). `id` is a uuid4 generated by
  the API, stored as `uuid`, returned as its canonical string (unchanged for callers).
- **Fail at startup only for missing configuration** (AC-002.14): the lifespan reads `DATABASE_URL`; when it is
  unset or blank it logs one error line naming `DATABASE_URL` and raises, so uvicorn never binds the port and exits
  with status 3. A database that is merely unreachable never stops startup (AC-002.11): the lifespan does not
  connect at all.
- **`/health` never touches the database** (AC-002.9); **`/ready` is `SELECT 1` with a 0.5 s deadline** and does not
  run migrations (AC-002.8, AC-002.10).
- **`create_app()` factory** in `main.py`, with the module-level `app = create_app()` kept for uvicorn
  (`taskboard4_api.main:app`). Each app instance owns its `Database` (in `app.state.db`), so tests can run two
  instances over one database (AC-002.2, AC-002.12) and "restart" one (AC-002.1).
- **Unexpected errors** get a JSON body `{"detail": "internal server error"}` with `500` (the system contract's
  error format); the metrics middleware still counts them.
- **Image smoke start:** the image no longer starts without `DATABASE_URL` (by design), and `/ready` needs a
  database. `scripts/image_smoke.sh` (`devbox run image-smoke`, also the repo's `ci-extra` gate) starts a throwaway
  Postgres next to the image and checks both the happy path and the refusal to start (AC-002.14 at image level).

Public interfaces (signatures only):

```python
# settings.py
class MissingSetting(RuntimeError): ...           # str(exc) == "DATABASE_URL is not set"
def load_database_url() -> str: ...               # os.environ["DATABASE_URL"].strip(); unset/blank -> MissingSetting

# db.py
CONNECT_TIMEOUT_S = 3            # libpq connect_timeout
STATEMENT_TIMEOUT_MS = 5000      # options="-c statement_timeout=5000" on every connection
POOL_WAIT_S = 2.0                # waiting for a free connection slot
OPERATION_DEADLINE_S = 7.0       # client-side deadline of a task operation (pool wait + statement)
READY_DEADLINE_S = 0.5           # client-side deadline of the readiness check (also its pool wait)
POOL_MAX_SIZE = 5

class DatabaseUnavailable(Exception):
    reason: str                  # "timeout" | "pool_timeout" | "connection" | "not_initialized"

class Database:
    def __init__(self, url: str) -> None: ...     # no I/O
    def run(self, op: Callable[[psycopg.Connection], T], *, deadline: float = OPERATION_DEADLINE_S) -> T: ...
        # ensures the schema once, runs op inside one transaction, commits; raises DatabaseUnavailable
    def ping(self) -> bool: ...                   # SELECT 1 within READY_DEADLINE_S, no schema check, never raises
    def close(self) -> None: ...                  # closes idle connections, shuts the executor down without waiting

def get_database(request: Request) -> Database: ...   # request.app.state.db, else DatabaseUnavailable("not_initialized")

# migrations.py
ADVISORY_LOCK_KEY: int           # fixed 64-bit constant
MIGRATIONS: list[tuple[int, str]]   # [(1, "<DDL of table tasks>")]
def ensure_schema(conn: psycopg.Connection) -> None: ...   # idempotent, safe under concurrency

# tasks/store.py
class TaskStore:
    def __init__(self, db: Database) -> None: ...
    def add(self, title: str, due_date: date | None) -> Task: ...
    def list(self) -> list[Task]: ...
def get_task_store(db: Annotated[Database, Depends(get_database)]) -> TaskStore: ...

# main.py
def create_app() -> FastAPI: ...
app: FastAPI = create_app()
```

`Database.run`, step by step:

```
submit worker to executor (max_workers = POOL_MAX_SIZE + 4); caller waits future.result(timeout=deadline)
worker:
  acquire slot (semaphore, timeout POOL_WAIT_S or the deadline if smaller)   -> pool_timeout
  conn = idle connection that passes a validation round trip, else psycopg.connect(url, connect_timeout=3,
         options="-c statement_timeout=5000")                                 -> connection
  if not schema_ready: ensure_schema(conn) (own transaction); schema_ready = True   (flag + lock per Database)
  with conn.transaction(): result = op(conn); if abandoned.is_set(): raise _Abandoned  (rollback, no commit)
  return conn to idle if healthy and idle, else close it; release slot
caller on future timeout: abandoned.set(); raise DatabaseUnavailable("timeout")
psycopg.OperationalError / InterfaceError (incl. QueryCanceled, LockNotAvailable) -> DatabaseUnavailable("connection")
anything else (ProgrammingError, IntegrityError, ...) propagates -> 500
```

## Contract

The request/response contract of spec 001 ([design](../001-create-and-list-tasks/design.md)) is unchanged and
binding (AC-002.3). This spec adds:

| Endpoint | Condition | Status | Body |
|---|---|---|---|
| `POST /tasks` | valid body, database reachable | `201` | Task object `{"id", "title", "due_date"}` |
| `POST /tasks` | invalid body or invalid JSON, database reachable **or not** | `422` | FastAPI validation body, `loc[-1]` names `title` / `due_date`; `json_invalid` for bad JSON (AC-002.4) |
| `POST /tasks` | valid body, database refuses/drops connections, does not answer, or no free connection in 2 s | `503` within 10 s (in practice about 2 s refused, at most 7 s silent) | `{"detail": "database unavailable"}`; no task stored (AC-002.5, AC-002.6, AC-002.7) |
| `GET /tasks` | database reachable | `200` | bare array, ordered by creation (`seq`) across all instances |
| `GET /tasks` | database unavailable as above | `503` within 10 s | `{"detail": "database unavailable"}` |
| `GET /health` | process runs (database state irrelevant) | `200` | `{"status": "ok"}` (AC-002.9) |
| `GET /ready` | `SELECT 1` succeeds within 0.5 s | `200` | `{"status": "ready"}` |
| `GET /ready` | it fails, times out, or the app has no database (lifespan not run) | `503` within 1 s | `{"status": "not ready"}` (AC-002.8) |
| any | unexpected error | `500` | `{"detail": "internal server error"}` |

The `503` body is exactly `{"detail": "database unavailable"}` for every database failure; no driver message,
host or SQL ever reaches a caller. Responses carry `Content-Type: application/json`.

**Startup without `DATABASE_URL`** (unset or only whitespace) (AC-002.14): the process writes one structured log line
to stdout, for example

```json
{"event": "config_missing", "variable": "DATABASE_URL", "message": "DATABASE_URL is not set", "level": "error", "timestamp": "..."}
```

then uvicorn logs `Application startup failed. Exiting.` and the process exits with status `3`; the port is never
bound. Tests assert: exit status non-zero, some output line contains `DATABASE_URL`, `/health` never answered.

**`DATABASE_URL`** accepts `postgres://` and `postgresql://` (libpq parses both; no rewriting) (AC-002.13). Its value
is never logged. No other connection variable (`PG*`) is read.

**Logs** (structlog JSON, stdout): `task_created` (`task_id`) as today; `database_unavailable` (warning,
`operation`: `add` | `list` | `ready`, `reason`: see `DatabaseUnavailable.reason`); `schema_migrated`
(`version`) when this instance applied a migration. No titles, no URL, no password.

## Data

Migration 1 (in `MIGRATIONS`), applied in one transaction after `SELECT pg_advisory_xact_lock(ADVISORY_LOCK_KEY)`:

```sql
CREATE TABLE IF NOT EXISTS schema_version (
  version    integer PRIMARY KEY,
  applied_at timestamptz NOT NULL DEFAULT now()
);
-- skipped when schema_version already holds 1
CREATE TABLE IF NOT EXISTS tasks (
  seq        bigserial    PRIMARY KEY,
  id         uuid         NOT NULL UNIQUE,
  title      varchar(200) NOT NULL,
  due_date   date         NULL,
  created_at timestamptz  NOT NULL DEFAULT now()
);
INSERT INTO schema_version (version) VALUES (1);
```

- Insert: `INSERT INTO tasks (id, title, due_date) VALUES (%s, %s, %s) RETURNING id, title, due_date`.
- List: `SELECT id, title, due_date FROM tasks ORDER BY seq`.
- `title` is already trimmed and at most 200 characters (model validation), so `varchar(200)` never truncates.
  `due_date` is a Python `date`; psycopg maps it to `date` and back, so the API returns exactly what was sent.
- The schema flag is per `Database` instance (per process). A restarted instance runs `ensure_schema` once more; it
  is a no-op under the lock.

## Test seam (for the testers, binding)

- **Postgres for tests:** a session fixture uses `TEST_DATABASE_URL` (a server URL with rights to create
  databases) when set, otherwise starts `postgres:16-alpine` with `testcontainers[postgres]` (a dev dependency
  added in t1). Docker is required for `devbox run test` without `TEST_DATABASE_URL`; GitHub's `ubuntu-latest`
  provides it.
- **Isolation:** a function fixture creates a fresh database (`CREATE DATABASE t_<uuid hex>`) and yields its URL;
  teardown drops it `WITH (FORCE)`. Every test starts with no schema, which also exercises AC-002.11 / AC-002.12.
- **App under test:** `monkeypatch.setenv("DATABASE_URL", url)`, then `with TestClient(create_app()) as c:` (the
  `with` runs the lifespan). A restart (AC-002.1) is leaving that block and entering a new one with a fresh
  `create_app()` on the same URL. Two instances (AC-002.2, AC-002.12) are two `create_app()` objects; for
  AC-002.12 start both lifespans concurrently (two threads), then use both.
- **Outages:** route the app through an in-test TCP proxy (a small threaded forwarder on a fixed local port in
  `tests/`) to the test Postgres. `refuse()` closes the listener and resets open connections (AC-002.5, AC-002.10,
  AC-002.11), `blackhole()` accepts and holds connections and stops forwarding bytes (AC-002.6, "does not
  answer"), `restore()` forwards again on the same port. A container restart is not used: testcontainers maps a
  new host port after a restart. The lock case of AC-002.6 can use a side connection holding
  `LOCK TABLE tasks IN ACCESS EXCLUSIVE MODE` (answered `503` by the server's 5 s `statement_timeout`).
- **AC-002.14:** start `python -m uvicorn taskboard4_api.main:app --port <free port>` as a subprocess with an
  environment without `DATABASE_URL`; wait at most 15 s for it to exit; assert a non-zero status, a line containing
  `DATABASE_URL` in its combined output, and that `/health` on that port never answered.
- **Spec 001's tests** run unchanged in their assertions against Postgres: only their `tclient` fixture changes
  (fresh database + `create_app()`), and `test_restart_empties_list` (AC-001.10, withdrawn) is deleted. The
  template's `tests/conftest.py` `client` fixture and `tests/test_health.py::test_ready_returns_ready` need the same
  database fixture, since `/ready` now checks the database.

## Risks

- **Late commit after a deadline:** if the database freezes between the `INSERT` and the `COMMIT` of a request,
  the commit can still land after the caller got `503`. The contract covers this ("no assumption that a task was or
  was not stored"); AC-002.7's scenario (database unavailable before the request) cannot hit it, because the worker
  checks the abandoned flag before committing.
- **Stuck workers on a frozen server** hold up to `POOL_MAX_SIZE` connections and executor threads; further
  requests answer `503` after the pool wait, and `/ready` after 0.5 s. They free themselves when the server
  answers again or the TCP connection breaks.
- **Rollout with two replicas:** the old in-memory pods and new Postgres pods serve side by side for one rollout;
  tasks created on an old pod are lost (non-goal). The gitops slice (`DATABASE_URL`, 2 replicas) must land first,
  otherwise the new pods exit at startup (AC-002.14) and the rollout stalls on the old ReplicaSet.
- **Docker in CI:** the tests and `image-smoke` need Docker on the CI runner; a self-hosted `CI_RUNNER` without
  Docker fails `test` and `ci-extra` (see human steps in the plan).
