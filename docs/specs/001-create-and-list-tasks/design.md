# Design — 001 Create and list tasks

## Decisions

- **A `tasks` package with three small modules** (models, store, api) next to the existing `main.py`, wired in with `app.include_router(...)`. The routes on `main.py` stay where they are. Later task features (read one task, update, delete) extend this package.
- **In-memory store behind a FastAPI dependency.** `TaskStore` keeps tasks in a Python list (insertion order is creation order, AC-001.9) and guards it with a `threading.Lock`, because the sync endpoints run in FastAPI's threadpool. One module-level instance per process, so a restart starts empty (AC-001.10). Routes get it through `Depends(get_task_store)`. Tests swap it with `app.dependency_overrides[get_task_store]`, so every test starts from an empty store (AC-001.8) and a "restart" is a fresh `TaskStore()`. The store is not shared between replicas: that is a non-goal in the spec, and it means the gitops entry must run one replica until there is storage.
- **Ids are `str(uuid.uuid4())`**: always non-empty and unique without a counter (AC-001.1, AC-001.3). The service generates them; callers cannot set them.
- **FastAPI's default 422 body is the error format.** It already names the field in `loc` and also covers malformed JSON (AC-001.7). No custom handler, and no problem+json yet: one consistent format for all of the service's validation errors.
- **Strict input types.** `title` is `StrictStr`, so `123`, `true`, `null`, `[]` and `{}` are rejected instead of coerced (AC-001.4). `due_date` is a `StrictStr` matched against `^\d{4}-\d{2}-\d{2}$` and then parsed with `datetime.date.fromisoformat`. Pydantic's built-in `date` type is not used because it also accepts Unix timestamps and datetime strings with a zero time, which AC-001.6 rejects.
- **Title trimming comes before validation.** Leading and trailing whitespace is stripped first, then the length must be 1–200 characters. So `"   "` fails (AC-001.4), `"  Buy milk  "` is stored as `"Buy milk"` (AC-001.11), and the 200-character limit applies to the trimmed title (AC-001.5).
- Past due dates are accepted as given (AC-001.12). No "today" check exists.

No ADR: everything here is local to this feature.

Public interfaces (signatures only):

```python
# models.py
Title = Annotated[StrictStr, StringConstraints(strip_whitespace=True, min_length=1, max_length=200)]

class TaskCreate(BaseModel):
    model_config = ConfigDict(extra="ignore")
    title: Title
    due_date: date | None = None          # input: StrictStr "YYYY-MM-DD" or null, validated in a field_validator(mode="before")

class Task(BaseModel):
    id: str
    title: str
    due_date: date | None                 # serialized as "YYYY-MM-DD" or null

# store.py
class TaskStore:
    def add(self, title: str, due_date: date | None) -> Task: ...   # assigns the uuid4 id, appends under the lock
    def list(self) -> list[Task]: ...                               # copy, in creation order

def get_task_store() -> TaskStore: ...    # returns the module-level instance
```

## Contract

All bodies are `application/json`. Fields are snake_case. A task object always has exactly these three keys:

```json
{"id": "6f1c…-uuid4", "title": "Buy milk", "due_date": "2026-12-31"}
```

| Field | Type | Rules |
|---|---|---|
| `id` | string | non-empty uuid4, generated by the service, unique per task (AC-001.1, AC-001.3) |
| `title` | string | trimmed; 1–200 characters after trimming (AC-001.4, AC-001.5, AC-001.11) |
| `due_date` | string `YYYY-MM-DD` or `null` | a real calendar date; past dates allowed; `null` when omitted (AC-001.1, AC-001.2, AC-001.6, AC-001.12) |

### `POST /tasks`

Request body: `{"title": string, "due_date"?: string | null}`. Unknown extra keys are ignored. A body that is not a JSON object (an array, a string, malformed JSON) is rejected.

| Case | Status | Body |
|---|---|---|
| valid | `201 Created` | the created task object |
| `title` missing, `""`, whitespace only, not a string, or longer than 200 characters after trimming | `422` | validation error, one entry with `loc` `["body", "title"]` (AC-001.4, AC-001.5) |
| `due_date` not a string or `null`, not `YYYY-MM-DD`, or not a calendar date (`2026-13-01`, `2026-02-30`, `tomorrow`, `2026-12-31T10:00:00Z`) | `422` | validation error, one entry with `loc` `["body", "due_date"]` (AC-001.6) |
| body is not valid JSON | `422` | validation error, entry `type` `"json_invalid"` (AC-001.7) |

A rejected request never adds a task.

### `GET /tasks`

`200 OK` with a bare JSON array of task objects, oldest first. It is `[]` when no task exists since the process started (AC-001.8, AC-001.9, AC-001.10). No query parameters.

### Validation error format (FastAPI default, binding)

```json
{
  "detail": [
    {"type": "string_too_long", "loc": ["body", "title"], "msg": "…", "input": "…"}
  ]
}
```

- `detail` is a non-empty array. Each entry has `type` (string), `loc` (array), `msg` (string) and `input`. It may also carry `ctx` and `url`.
- "The body names the field" means: at least one entry's `loc` ends with the field name (`"title"` or `"due_date"`). Tests assert on `loc`, not on `msg` wording or `type` values, except `json_invalid` for AC-001.7.

### Test seam

```python
from taskboard4_api.main import app
from taskboard4_api.tasks.store import TaskStore, get_task_store

store = TaskStore()
app.dependency_overrides[get_task_store] = lambda: store   # empty store per test; a new TaskStore() simulates a restart
```

Smoke tests (AC-001.1, AC-001.9) run against a deployed instance with an unknown amount of earlier data. They create `smoke-<uuid>` titles, are marked `@pytest.mark.writes`, and check that their own tasks appear in `GET /tasks` in the order they created them, not that the list is exactly `[A, B, C]`.

## Data

There is no persistent data. Each process holds one `list[Task]` in memory, with no cap (non-goal).

## Risks

- **Multiple replicas** would each keep their own list, so `GET` would return different results depending on which pod answers. The spec accepts this as a non-goal. The deployment should stay at one replica until a storage spec lands. This plan changes nothing in gitops.
- **Unbounded memory**: there is no cap, by the spec's choice. Acceptable for the demo stage.
